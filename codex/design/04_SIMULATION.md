# セル物理と空間管理

単位・ID・保存則は[共通契約](02_CONTRACTS.md)、phaseは[アーキテクチャ](03_ARCHITECTURE.md)を参照します。

## チャンクと参照実装

チャンクは64×64のCellCore配列とsidecar、活動領域、境界versionを持ちます。最初にdense参照実装を作り、同じ全域走査をchunk store上で再現します。chunk単位で全64行を処理する順序は全域のy/x順と異なるため採用しません。世界行ごとに該当chunk行へアクセスします。

各chunkの生セルは16KiBですが、stampは32KiB、熱は16KiB、timerとmetadataも別途必要です。4バイトcellのみからキャッシュ効率を断言しません。scratchは必要chunkだけに確保・再利用し、起動時の容量予約後はtick内の再確保を避けます。

局所演算は最大8セル先まで読み書き可能とします。移動経路は各セルを検査し、壁を飛び越えません。境界を跨ぐ操作は双方を同一所有者が予約・更新します。haloを入れる場合は読み取り専用cacheであり、正規状態の二重所有はしません。

## 移動演算

1. y/xの正規順でセルを取得。empty、移動stamp済み、静止固体を除外する。
2. behaviorと固定ruleから候補を生成する。候補順の左右差は座標/tick/domainの乱数で決める。
3. 出発点と到着点がLoadedか、経路が許可されるか、stampが未処理かを確認する。
4. CellCore・energy・timerを一括交換する。両方のstampを現tickにする。
5. 両地点と依存範囲をwake、描画・衝突cacheを無効化する。

失敗した移動では状態を消費しません。試行回数は固定上限。原子交換のため移動前後の物質別セル数が等しいことは、交換の置換性から確認できます。stampは物質に付随せず、移動に参加した場所の処理管理です。

| behavior | 1.0のモデル |
| --- | --- |
| Solid | 静止支持。局所破断後はfallingとして粉体ルールで落下 |
| Powder | 下、斜め下、許可された密度交換。最大落下距離は8 |
| Liquid | 下、斜め下、水平探索。empty/軽い流体との交換。非圧縮圧力solverなし |
| Gas | 上向き・横方向へ局所交換。閉じた領域では蓄積し、寿命で黙って消えない |
| Empty | occupied tokenを持たない。熱場の空間としては存在 |

密度順位が等しい物質同士は密度交換しません。浮力や流量はゲーム用係数で、現実のナビエ–ストークス方程式の解とは称しません。1.0では1セルの部分充填、圧縮、連続圧力を追加しません。水柱・左右偏り・狭い流路の不自然さは評価場面で調整します。

instance attachmentも交換トランザクションへ参加します。移動で同じinstance IDを維持し、座標indexを更新。material変換はattachmentごとの明示transfer/drop ruleを使い、未定義なら変換を拒否します。sidecarやcomponent容量不足で属性だけ失うことはありません。

## 崩落

P4は現在のセルと8近傍、4×4領域の占有を使った局所支持ルールです。anchor材は落下しません。可崩落材は下方向の支持、近傍の接合、領域充填率から固定閾値でfallingを決めます。P4内ではsnapshotから判定し、最後にflagをcommitします。

これは局所的な削れ・粒子崩落モデルです。構造全体の重心や根元への連結を解くモデルではなく、長い橋や浮遊島の力学的崩壊を保証しません。falling解除は支持成立と着地で行い、閾値にヒステリシスを設けます。4×4密度をplayerの通行許可に流用しません。

崩落の損傷が必要な場合は専用sidecarを追加するADRを先に作ります。回転剛体化や広域支持グラフは1.0外です。

## 熱と反応

現行実装注記（thermal solverはSIM v5で導入、現在のWorldはSIM v10）: `World`は有限矩形とremote chunkの各cellに`i32` thermal energy sidecarを持ち、World生成時に有限領域のP6用delta/output scratchを確保します。有限領域は等熱容量・一定係数1/8の整数scalar solverで拡散し、移動演算はCellCoreとenergyを一緒にswapします。inactive finite chunkとの対fluxはマスクし、凍結中はenergyを保持します。remote energyは移動・snapshot・fingerprint/hash対象ですが、remote内の拡散solverとfinite/remote間masked fluxは未実装です。material別`c/k`、相転移・燃焼も未実装です。従って下記のenthalpy設計全体が実装されたわけではなく、M4出口も未通過です。

熱の正規値はゲーム用固定エネルギー量`E:i32`、顕熱容量`c`は1〜255の整数です。相変化しない材の温度は有理数`T=E/c`。相変化familyは共通energy原点を持つ単調なpiecewise enthalpy tableから有理数温度を求め、潜熱区間では温度を一定にします。表示だけでfloorし、flux計算前に温度を整数丸めしません。物質変換時にもenergyを引き継ぎます。emptyも基準熱容量を持ち、セル交換時にenergyを交換します。温度のSI換算は演出上のmappingです。

P6開始snapshotから、右・下の各隣接対を1度だけ評価します。導電係数`k`は`u32`の0〜65536を65536で割って0〜1を表します。対の係数は両materialの小さい方を使います。`c_safe`は各materialのenthalpy family全顕熱区間の最小容量（相変化なしならc）。対の移動量は次式です。

```text
q = trunc((T_a - T_b) * min(c_safe_a, c_safe_b) * k / 8)
delta[a] -= q
delta[b] += q
```

実装ではkの65536分母も適用し、有理数積は`i128`、delta累積は`i64`以上で保持します。1セルは最大4辺を持ち、各辺係数を1/8以下にする保守的な制限で過大な陽解法更新を避けます。熱源/反応なしの伝導に対し、離散丸めによる小差の停止を許容し、安定性・最大値原理・energy保存をV05で検証します。上限に収まらない入力/熱源はcommit前に拒否し、保存量を変えるsaturating clampをしません。

相転移は単位トークン1個を1個へ変換し、物質群に共通のenthalpy閾値で固体/液体/気体を定義します。潜熱区間中は遷移元のmaterialを維持し、区間終端で遷移します。区間順・顕熱容量・温度単調性・復帰側閾値を登録時に検証します。負方向への冷却も同じtableを使用し、family member別の単純なE/cへ切り替えて温度を跳躍させません。P6開始状態から求めた熱をcommit後、相転移、反応、timerの順で進めます。

反応は登録済み疎リストを物質対ごとに整理し、条件を優先順位・rule ID順で評価します。全65k×65kの密行列を確保しません。対検索の後、候補数に比例した処理であり、無条件O(1)とは称しません。反応は方向性を保持し、対称なruleだけを両方向に展開します。

同phaseに1セルが複数反応へ参加しないよう専用reservationを使います。生成物に隣接emptyが必要なら先に予約し、足りなければ反応全体を延期します。連鎖反応は次tickへ送ります。反応前後の物質台帳と熱源/吸収量を記録します。

## スリープとDirty

render Dirtyとphysics活動候補は別です。視覚が変わらなくても熱やtimerは活動します。

最初は全chunk起床。次に**全域を走査する参照実装と同じ結果になること**を確認しながら、sleep/Dirtyを導入します。候補移動が全て失敗し、熱delta=0、相転移/反応/timer/確率的遷移なし、pending操作なしで恒等となる領域だけがsleep候補です。

更新があった地点pに対して、次tickの候補はpをChebyshev距離8で膨張した領域を含めます。現在tickでまだ走査していない地点への影響は即座に現在の活動集合へ追加し、既に走査した地点は次tick候補へ入れます。活動集合は順序付き区間で、追加後もC04の順序を変えません。

局所演算の依存が連鎖してDirtyを広げる場合も、全域参照で本来訪問される未走査セルを取りこぼしません。これが実装困難・高コストな場合はchunk全体と隣接chunkを起床させます。最適化のために物理を黙って1tick遅らせません。

境界変更、配置、移動、生成、熱源、entity接触、timer期限はwake理由です。確率的反応が起こり得るchunkは常時活動させます。tickの偶奇が変わるだけで候補が発生する場合も恒等ではありません。load後は活動cacheを再生成して全domainを起床します。

## 物質を持つ粒子

視覚粒子と正規物質粒子は別poolです。1.0で砂・水の飛散を物質粒子に変える場合、1セル↔1トークンをatomicに変換し、material/energy/stateを保持します。着地先が塞がっていれば近傍探索、待機、再試行を行い、消滅させません。pool不足ならセルのままです。entityへのダメージを与える粒子は必ず正規側に置きます。
