# 検証作品と要求の対応

## 判定する対象

TerrariaとNoitaの完全クローンが、SDKを使う通常の作者として制作できることをv1の受入条件にする。本書のT/Nは段階的に統合を検証する経路であり、これらだけを通して完全クローン制作能力を合格にしない。[26の全内容・全挙動台帳](26_FULL_CLONE_ACCEPTANCE.md)と[25の置換可能な基盤](25_OPEN_EXTENSION_AND_COLLISION_CONTRACTS.md)が最終判定を定める。原作の全コンテンツをエンジンへ同梱する必要はないが、作者が全内容を実装できる具体的な経路を確認する。

作例のゲーム固有コードは`examples/`等の独立したprojectに置き、エンジンmoduleへの特例分岐を禁止する。作例の権限と公開APIが通常projectと一致することをreviewする。

## 共通の独自拡張検証

別projectで、基本マテリアルにない挙動、独自component、独自EffectNode、独自装置、独自UIを追加する。コードの変更はそのprojectと追加crateに限定し、エンジン本体を変更しない。

追加した状態を保存・復元し、必要なら4clientへ複製する。新しい素材の見た目、動作、個体状態、scriptではなくRustで書いた独自処理が、元の基盤へ接続できることを検証する。V1-29/V1-31/V1-32の必須証拠とする。

## 到達判定の記録

各作品の経路ごとに、source revision、content pack、保存データ、実行手順、操作記録、動画または画面記録、正規stateの検査、性能、APIの不足、review結果を保存する。動画だけを正しさの証拠にせず、内部のfixtureだけを制作可能性の証拠にもしない。

クローン制作に必要な仕組みが表にないと判明した場合は、V1-32の不足として仕様へ追加し、実装と検証を行う。単にこの表に書かれていなかったことを理由に対象外へしない。
