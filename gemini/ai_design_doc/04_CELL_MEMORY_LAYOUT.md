# 32-bit セル完全メモリレイアウト & キャッシュライン設計 (`ai_design_doc/04_CELL_MEMORY_LAYOUT.md`)

> **本書の目的**  
> 1 セルあたり厳密に 4 バイト（32-bit）固定サイズを保証し、ハードウェアの L1 データキャッシュ（L1D）ライン（64 バイト）への完全適合と SIMD 自動ベクトル化を可能にするメモリレイアウトを定義します。

---

## 1. ビットレベル・アライメント仕様

```text
       Byte 0 & 1 (16-bit)               Byte 2 (8-bit)        Byte 3 (8-bit)
  ┌─────────────────────────────────┬─────────────────────┬─────────────────────┐
  │         material: u16           │      flags: u8      │      data: u8       │
  │   (マテリアル ID: 0..65535)     │ (直交状態フラグ 8bit)│(テクスチャ/追加物性)│
  └─────────────────────────────────┴─────────────────────┴─────────────────────┘
```

### フィールド詳細仕様
1. **`material: u16` (16-bit)**:
   * 物質識別番号。65,536 種類の物質を表現可能。
   * `0` は常に空虚（`AIR`）として予約。
2. **`flags: u8` (8-bit)**:
   * 直交ビットマップ。
   * `Bit 0` (`FLAG_CLOCK` = 1 << 0): 更新クロックトグル（二重移動防止）。
   * `Bit 1` (`FLAG_FALLING` = 1 << 1): 自由落下・崩落中フラグ。
   * `Bit 2` (`FLAG_BURNING` = 1 << 2): 燃焼中フラグ。
   * `Bit 3` (`FLAG_WET` = 1 << 3): 濡れフラグ。
   * `Bit 4` (`FLAG_FROZEN` = 1 << 4): 凍結フラグ。
   * `Bit 5` (`FLAG_ELECTRIFIED` = 1 << 5): 帯電フラグ。
   * `Bit 6..7`: 将来用予約。
3. **`data: u8` (8-bit)**:
   * 物質種別に応じたコンテキストデータ。
   * 固体ブロックの場合: 8x8 テクスチャサンプリングインデックス（`0..63`）。
   * 流体の場合: 局所水圧 / 深度値。
   * 炎・ガスの場合: 残り寿命（tick）。

---

## 2. キャッシュライン適合性（L1D Cache Line Fit）

現代の x86_64 および ARM64 プロセッサの L1 データキャッシュラインサイズは厳密に **64 バイト** です。

$$ \text{Cells per Cache Line} = \frac{64 \text{ Bytes}}{4 \text{ Bytes/Cell}} = 16 \text{ Cells} $$

* 1 回のキャッシュラインフェッチで **連続する 16 ピクセルのセルデータ** が CPU レジスタ直近にロードされます。
* セルのサイズが 5 バイトや 8 バイトに膨らむとキャッシュライン境界を跨ぐ（Cache Line Split）が発生し、メモリ帯域消費が 2〜4 倍に激増してフレームレートが暴落します。本エンジンの 4 バイト設計はこれを 100% 回避します。

## 3. 型定義とコンパイル時アサーション

```rust
#[derive(Clone, Copy, PartialEq, Eq, Default, Debug)]
#[repr(C, align(4))]
pub struct Cell {
    pub material: u16,
    pub flags: u8,
    pub data: u8,
}

// コンパイル時サイズ保証（CI / ビルド時に即死検出）
const _: () = {
    assert!(std::mem::size_of::<Cell>() == 4);
    assert!(std::mem::align_of::<Cell>() == 4);
};
```
