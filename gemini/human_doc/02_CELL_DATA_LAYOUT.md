# 32bit セルの直交ビットレイアウト設計 (`02_CELL_DATA_LAYOUT.md`)

> **本書の目的**  
> マテリアル ID の組み合わせ爆発を完全に防ぎ、物質の種類（**最大 65,535 種**）と動的物理状態（崩落・燃焼・流動等）を直交して表現する、厳密な 32bit（4 バイト）セルのデータレイアウトを定義します。

---

## 1. 32bit セル構造体の完全仕様

メモリ上で 1 セルあたり厳密に **4 バイト（32-bit）** を維持し、CPU の 64 バイト・キャッシュラインに 16 個のセルが隙間なく格納されるように設計します。

```text
       Byte 0 & 1 (16-bit)               Byte 2            Byte 3
  ┌─────────────────────────────────┬─────────────────┬─────────────────┐
  │         material: u16           │   flags: u8     │    data: u8     │
  │   (物質固有 ID 65,536 種類)     │  (動的状態 8bit)│ (テクスチャ/値) │
  └─────────────────────────────────┴─────────────────┴─────────────────┘
```

### Rust による完全な定義
```rust
/// ワールドを構成する 1 ピクセルの完全なデータ構造。
/// 4 バイト固定サイズ（repr(C, align(4))）により、キャッシュ効率を最大化。
/// 16-bit ID により、テラリア規模（数千〜1万個以上）のブロックを自由に追加可能。
#[derive(Clone, Copy, PartialEq, Eq, Default, Debug)]
#[repr(C, align(4))]
pub struct Cell {
    /// 物質の固有 ID（0 = AIR, 1 = DIRT, 2 = STONE, 3 = WATER, 4 = SAND, ... 最大 65,535 種）
    /// 一時的な状態（崩落など）でこの値を変更してはならない。
    pub material: u16,

    /// セルの動的物理状態フラグ（各ビットが直交した意味を持つ）
    pub flags: u8,

    /// コンテキスト依存データ（8x8 テクスチャサンプリングインデックス 0..64、炎の寿命、水圧など）
    pub data: u8,
}
```

## 2. システム状態フラグ (`flags: u8`) の直交ビットマップ

`flags` の 8 つのビットは、互いに干渉しない独立した意味を持ちます。

| ビット | 名称 | 定数名 | 役割と解説 |
|---|---|---|---|
| **Bit 0** | クロック | `FLAG_CLOCK` | 今 tick 処理済みかを判定するトグルビット。二重移動・無限加速を防止。 |
| **Bit 1** | 崩落中 | `FLAG_FALLING` | **★核心**。本来 Solid である土や石でも、このフラグが立てば **砂と同様に重力落下・滑落** する。 |
| **Bit 2** | 流動中 | `FLAG_FLOWING` | 水流などの外力によって横方向に押し流されている最中であることを示す。 |
| **Bit 3** | 燃焼中 | `FLAG_BURNING` | 炎に包まれており、熱を周囲に拡散して寿命（`data`）経過後に灰へ変化する。 |
| **Bit 4** | 湿潤 | `FLAG_WET` | 水に触れて濡れている状態。着火しにくくなり、特定反応（泥化など）のトリガーとなる。 |
| **Bit 5..7**| 予備 | - | 将来の拡張用（凍結 `FROZEN`、帯電 `ELECTRIFIED` など）。 |

### フラグ操作ヘルパー関数の実装例
```rust
pub const FLAG_CLOCK: u8   = 1 << 0; // 0b00000001
pub const FLAG_FALLING: u8 = 1 << 1; // 0b00000010
pub const FLAG_FLOWING: u8 = 1 << 2; // 0b00000100
pub const FLAG_BURNING: u8 = 1 << 3; // 0b00001000
pub const FLAG_WET: u8     = 1 << 4; // 0b00010000

impl Cell {
    /// 崩落中（落下中）であるかを判定
    #[inline]
    pub fn is_falling(&self) -> bool {
        (self.flags & FLAG_FALLING) != 0
    }

    /// 崩落フラグを設定または解除
    #[inline]
    pub fn set_falling(&mut self, falling: bool) {
        if falling {
            self.flags |= FLAG_FALLING;
        } else {
            self.flags &= !FLAG_FALLING;
        }
    }
}
```

## 3. なぜこの設計で「組み合わせ爆発」が完全に消滅するのか？

### 従来（欠陥設計）
* `DIRT`（土）
* `LOOSE_DIRT`（崩落土）
* `BURNING_DIRT`（燃える土）
* `WET_DIRT`（濡れた土）  
$\to$ 物質が増えるたびに ID を何倍も消費し、256 種の上限に即座に達する。

### 本設計（直交設計）
* 物質 ID は **常に `DIRT`（1）** のまま。
* 「崩落している」 $\to$ `flags |= FLAG_FALLING`
* 「燃えている」 $\to$ `flags |= FLAG_BURNING`
* 「濡れている」 $\to$ `flags |= FLAG_WET`

```rust
// 例: 「削られて崩落しながら燃えている土」の表現
let cell = Cell {
    material: DIRT,
    flags: FLAG_FALLING | FLAG_BURNING,
    tex_coord: 15,
    data: 120, // 炎の残り寿命
};
```

1 つのマテリアル ID に対し、**$2^5 = 32$ 通りの状態の組み合わせ** を ID 枠の消費ゼロで表現できます。  
これにより、**純粋な物質を 256 種類フルにエンジンに実装可能** となります。

## 4. `data: u8` のコンテキスト別活用ルール

`data` フィールド（1 バイト: 0〜255）は、マテリアルやフラグに応じて以下のように再利用します：

| セルの状態 | `data` の使途 | 内容 |
|---|---|---|
| **液体（WATER 等）** | `fall_momentum` (0..7) | 落下時の加速段階。値が大きいほど 1 tick で多くのセルを落下。 |
| **粉体 / 崩落セル** | `slide_direction` (0..1) | 斜面を滑り落ちる際の左右の優先慣性。 |
| **燃焼セル (`FLAG_BURNING`)** | `burn_life` (0..255) | 炎の残存フレーム数。0 になると消滅または灰マテリアルへ変化。 |
| **気体（SMOKE, STEAM）** | `dispersion_life` (0..255) | 大気中に上昇・拡散して消滅するまでの寿命。 |
