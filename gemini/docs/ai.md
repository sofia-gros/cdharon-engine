# Charon Engine コアアーキテクチャ仕様書

## 1. プロジェクト概要と設計思想

* **名称:** Charon Engine
* **ジャンル:** 2D Falling Sand（セル・オートマトン）物理サンドボックスエンジン
* **技術スタック:** Rust, `winit` (0.29), `pixels` (0.13), `serde`
* **参考リポジトリ (PieKing1215氏の実装アプローチを参考):**
* Falling Everything Engine: `[https://github.com/PieKing1215/FallingSandEngine](https://github.com/PieKing1215/FallingSandEngine)`
* Falling Sand Survival: `[https://github.com/PieKing1215/FallingSandSurvival](https://github.com/PieKing1215/FallingSandSurvival)`
* Noita, Terraria


* **コア設計思想 (究極の最適化):**
* ピクセル単位の物理計算（粉体の落下等）と、チャンクベースの流体力学（マクロなベクトル移動）をハイブリッドで処理する。
* 静止状態（海の中など）のピクセルは計算を完全にスキップ（SLEEP）し、$O(N^2)$ の計算負荷を排除する。
* 状態保存によるデータ肥大化を防ぐため、Dirtyチャンク管理とRLE（ランレングス圧縮）を前提とした設計とする。



## 2. メモリアーキテクチャ：64bit セル構造

ワールドは単一の1次元配列 `Vec<u64>` として管理する。

### ビットレイアウト (u64)

```text
[ 24bit: 色情報 (RGB 888) ]         // 描画用のフルカラー情報
[ 16bit: バリアブル・データ ]       // コンテキスト依存の可変変数 (Q8.8 速度など)
[ 16bit: マテリアルID ]             // 0番を「空気(AIR)」として定義
[  8bit: システム状態フラグ ]       // 物理演算の制御フラグ

```

### システム状態フラグ (8bit)

* `Bit 0: UPDATED` (今フレームで更新済みか。二重移動防止)
* `Bit 1: SLEEP` (静止ブロック状態。流体の底などで計算を完全にスキップする)
* `Bit 2: ACTIVE` (現在動いている自由セル。落下中・流動中など)

### バリアブル・データ (16bit) のエンコード

* **ACTIVEな粉体・流体:** **Q8.8 固定小数点数 (符号付き `i16`)**
上位8bitを整数部（px/frame）、下位8bitを小数部として、重力加速や速度減衰を表現する。

## 3. シミュレーションのハイブリッド・ルール

すべてのピクセルを馬鹿正直に動かすのではなく、「静止」と「活動」をシームレスに切り替える。

### 1. マクロ・流体ベクトル（チャンク処理）

* 世界を 32x32 または 64x64 のチャンクに分割する。
* 巨大な水（海や川の底）はすべて `SLEEP` フラグを立てて計算をサボる。
* チャンク自体が「流速ベクトル（方向と強さ）」を持つ。
* 表面の `ACTIVE` な水や浮遊物は、周囲のピクセル圧力を計算するのではなく、**自分が属するチャンクのベクトル**を読み取ってスライド移動する（$O(1)$ 計算）。

### 2. ランダムティック浸食（Random Tick）と深度減衰

* 川底の `SLEEP` 状態の水を毎フレームすべて計算せず、チャンク内でランダムに数ピクセルのみをピックアップする。
* 選ばれた水ピクセルが土と隣接していれば、確率で土を `ACTIVE` な泥に変換して上に巻き上げる。
* 上に巻き上げられたピクセルは、上部の空気までの距離（深度）によってチャンクベクトルの影響度（速度）が変わり、表面に近いほど速く流れる（流砂現象のシミュレーション）。

### 3. 移動と衝突判定 (Bresenham & Swap)

* `ACTIVE` なセルが複数ピクセルを移動する際は、Bresenhamアルゴリズムで軌跡を走査し、すり抜けを防ぐ。
* 移動先のセルの `density`（密度：`MaterialRegistry` に静的定義）を比較し、相手が低密度なら Swap（交換）、高密度なら移動停止する。

## 4. AIへのコーディング指示（初期実装フェーズ）

上記アーキテクチャに基づき、まずはチャンク処理やマルチスレッドを省いた「フェーズ1〜2（最小構成コア）」の Rust コードを作成してください。

1. **要求ファイル:**
* `pixel.rs`: 64bitパック処理とフラグ/Q8.8のゲッター・セッター。
* `world.rs`: 単一の `Vec<u64>` 配列を用いた更新ループ（下から上への走査、左右の走査反転、UPDATEDフラグ処理）。
* `material.rs`: 静的な密度（Density）などを保持するレジストリ。


2. **実装スコープ:**
* `SLEEP` やチャンク流体力学の本格実装は後回しとする。
* まずは「砂（粉体）」が Q8.8 の速度を持って重力落下し、Bresenham走査で地形に衝突して積み重なる基本ループを、バグ（セルの消失・無限加速など）なしで確実に動作させること。
